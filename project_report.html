1. Introduction & Motivation

The Internet of Things (IoT) has fundamentally transformed how billions of devices communicate across global networks. Sensors, smart appliances, industrial controllers, healthcare monitors, and autonomous systems now form an expansive, heterogeneous mesh of edge devices—each constantly transmitting data over shared network infrastructure. By 2030, the number of connected IoT devices is expected to surpass 29 billion.

However, this explosive growth has dramatically expanded the attack surface for cybercriminals. IoT devices are, by design, resource-constrained: they have limited processing power, memory, and battery life. They often run lightweight, unpatched firmware and cannot support the computational overhead of traditional security solutions. This makes them prime targets for botnet recruitment, data exfiltration, and large-scale Distributed Denial-of-Service (DDoS) attacks.

Real-World Threat Example

The Mirai Botnet (2016) compromised over 600,000 IoT devices (IP cameras, DVRs, routers) and used them to generate a record-breaking 1.1 Terabit-per-second DDoS attack against Dyn DNS, taking down major sites like Twitter, Netflix, and Spotify for hours. This demonstrates that poorly secured IoT devices are not just a personal risk—they are a critical national infrastructure risk.

Why Existing Solutions Fail

  • Rule-Based Systems (Snort, Suricata): These rely on manually curated signature databases. They are completely blind to any attack that doesn't already have a known signature (zero-day attacks). They also require constant manual updates.
  • Traditional Machine Learning (SVM, Random Forest): These require extensive, time-consuming manual feature engineering by domain experts. They scale extremely poorly when the number of features and dataset size grows, which is the norm in IoT environments.
  • Early Deep Learning Models (LSTM, basic CNN): While better than traditional ML, they either capture only spatial features (CNNs) or only temporal sequences (LSTMs/GRUs), not both simultaneously. They also struggle catastrophically with severely imbalanced datasets where rare attacks go completely undetected.

This creates a clear and urgent gap: we need an intelligent NIDS that can autonomously extract both spatial structure and temporal context from raw network packet flows, handle severe class imbalances, and eventually be capable of detecting entirely novel, never-before-seen attacks.

2. Project Overview & Objectives

This project is structured in two distinct phases. Phase 1 (the focus of this review) involves faithfully replicating and benchmarking the architecture proposed in the base paper by Wang et al. (2024), extended with additional evaluation metrics. Phase 2 (future work) will introduce our novel Zero-Day Dual-Engine add-on.

Phase 1 Objectives

1

Replicate the Base Paper Model

Implement and train the exact 1D ResNeSt + BiGRU hybrid architecture as described by Wang et al. (2024), across three benchmark IoT datasets (UNSW-NB15, CIC-IDS2018, CIC-IOT2023) at 50, 100, and 200 epochs—yielding a comprehensive 45-run evaluation matrix.

2

Implement CTGAN for Class Imbalance

Apply a Conditional Tabular GAN (CTGAN) to synthesize realistic minority-class attack samples (e.g., Worms, Shellcode) before training, to prevent the model from over-predicting the dominant "Normal" traffic class.

3

Introduce Novel Evaluation Metrics

Go beyond the paper's reported metrics (Accuracy, F1) by additionally computing Precision, Recall, False Alarm Rate (FAR), Matthews Correlation Coefficient (MCC), per-packet Inference Latency (ms), and Throughput (Packets Per Second, PPS)—metrics that prove real-world edge-deployment viability.

4

Design the Dual-Engine Architecture

Architect our novel Zero-Day Guard Dual-Engine model for execution in Phase 2, where an unsupervised Autoencoder sits upstream of the supervised classifier to flag unknown attacks before classification.

Dataset Processing Pipeline

  • Min-Max Normalization: All numerical features are scaled to the [0, 1] range so that features with large absolute values (e.g., byte counts) do not dominate features with small values (e.g., flag bits).
  • Label Encoding: Categorical attack labels are converted to integer indices (0, 1, 2, ...) for the Softmax classifier.
  • CTGAN Synthesis (Imbalance Correction): The minority attack classes are upsampled by a Conditional Tabular GAN. Unlike random oversampling (SMOTE), CTGAN generates entirely novel, statistically valid synthetic samples that follow the conditional distribution of the real data for each class, producing a far more robust training set.
  • Train / Validation / Test Split: Standard 80/10/10 stratified split to ensure class proportions are maintained across all sets.

4.1 Stage 1: 1D ResNeSt Block (Spatial Feature Extractor)

A standard ResNet uses skip connections to allow gradients to flow freely through very deep networks, avoiding the vanishing gradient problem. ResNeSt (Residual Network with Split-Attention) enhances this further by integrating a Split-Attention mechanism.

What is a 1D Convolution?

In this context, the input is a flat vector of network flow features (e.g., [packet_length, byte_count, flag_bits, ...]). A 1D convolutional filter (kernel) slides along this vector, learning local patterns within adjacent features. A 1×3 kernel, for example, looks at 3 consecutive features at a time. This is far more efficient than converting the data to a 2D image first, which is what earlier deep learning NIDS approaches unnecessarily did.

How the 1D ResNeSt Block Works (Step-by-Step)

1

Input Splitting into Groups

The input feature map is split into r groups (Group 1 through Group r). Each group processes a portion of the features independently in parallel, allowing the model to learn different sub-representations of the network flow simultaneously.

2

1D Convolution (Conv 1×1, then Conv 1×3)

Each group passes through two consecutive 1D convolutions: a pointwise 1×1 convolution to adjust channel dimensions, followed by a depthwise 1×3 convolution to capture local feature interactions. The 1×1 and 1×3 refer to the kernel sizes along the single feature dimension.

3

Split-Attention Block

The outputs from all groups are summed together and passed through the Split-Attention block. This mechanism applies a global average pooling followed by a fully connected layer to generate a set of attention weights (one per group). Each weight tells the model "how much importance to assign" to that group's features. The final output is a weighted sum of all group outputs. This is what makes ResNeSt dramatically better than a plain ResNet for intrusion detection—it dynamically focuses on the most informative features.

4

Residual (Skip) Connection

The original input to the block is added directly to the output of the Split-Attention block (the skip connection). This residual addition ensures that gradient flows freely all the way back to early layers during backpropagation, making training deep networks stable and effective.

5

Final 1×1 Convolution + Output

A final pointwise convolution re-combines the features into the correct output shape. The result is a rich, spatially-extracted feature representation that captures multi-granularity patterns from the raw network flow—completely free of manual feature engineering.

4.2 Stage 2: BiGRU (Temporal Feature Extractor)

A Gated Recurrent Unit (GRU) is a type of Recurrent Neural Network (RNN) that is designed to capture dependencies in sequential data. Unlike a standard RNN, a GRU uses two gating mechanisms—a Reset Gate and an Update Gate—to selectively remember and forget information from past timesteps. This prevents the long-term dependency problem (vanishing gradients over long sequences).

A Bidirectional GRU (BiGRU) runs two GRUs in parallel on the same sequence—one forward, one backward—and concatenates their hidden states at each timestep.

Why Bidirectionality Matters for Network Packets

Consider a TCP connection. The SYN packet (connection request) makes full sense only when understood alongside the SYN-ACK (response) that comes later. A forward-only GRU only knows what happened before each packet. By also running a backward pass, the BiGRU learns what happens after each packet—giving the model a complete, contextual understanding of the entire network flow as one coherent event, not just a series of disconnected data points.

5. Our Novel Add-On: Zero-Day Dual-Engine Model

⚠ The Critical Flaw of Supervised-Only NIDS

The base paper's architecture is a closed-world supervised classifier. Its Softmax output layer forces it to assign every single packet to one of its N known training classes. If a brand-new Zero-Day attack (one never seen during training) hits the network, the model cannot say "I don't know." It is mathematically forced to misclassify it as the most similar known class—potentially Normal traffic. This is an unacceptable failure mode in real-world security deployments.

5.2 Engine 1: Deep Autoencoder (Zero-Day Guard)

An Autoencoder is an unsupervised neural network that consists of two halves:

  • Encoder: Compresses the input feature vector into a small, dense bottleneck representation (the latent space). For example, 49 input features → 32 → 16 → 8 neurons.
  • Decoder: Reconstructs the original feature vector from the bottleneck representation. For example, 8 → 16 → 32 → 49 neurons.
The Core Principle: Reconstruction Error

We train the Autoencoder exclusively on Normal (Benign) traffic. After training, the Encoder learns a very efficient, compact representation of what "normal" IoT traffic looks like. The Decoder learns to perfectly reconstruct it.

At test time: When a known attack pattern (e.g., DoS, Exploits) is fed in, the Encoder cannot compress it well into a "normal" latent space. The reconstruction is poor, resulting in a high Mean Squared Error (MSE) between the original input and the reconstructed output. When a Zero-Day attack is fed in, the reconstruction error is even higher, since the model has never encountered anything like it.

We define a dynamic threshold τ: if MSE > τ, the packet is flagged as anomalous. If MSE ≤ τ, it is passed to Engine 2.

Mathematical Definition

Given an input sample x and its reconstruction x̂ = Decoder(Encoder(x)):

MSE(x, x̂) = (1/n) × Σᵢ (xᵢ − x̂ᵢ)²

If MSE > τ → Flag as Zero-Day Anomaly
If MSE ≤ τ → Pass to Engine 2 (ResNeSt+BiGRU)

5.3 Engine 2: Known Attack Classifier (ResNeSt + BiGRU)

This is directly the architecture from the base paper (Section 4). When Engine 1 determines a packet has a low reconstruction error—meaning it resembles known traffic patterns—Engine 2 takes over and applies the full 1D ResNeSt + BiGRU pipeline to precisely classify it into one of the known attack categories or Normal traffic.

5.4 Evaluation Strategy: LOCO (Leave-One-Class-Out)

To rigorously prove that the Dual Engine genuinely detects Zero-Day attacks rather than just performing well on seen data, we use a LOCO evaluation protocol:

1

Completely remove one specific attack class (e.g., "Worms") from the training set of both Engine 1 and Engine 2.

2

Train the Dual Engine as normal on the remaining classes.

3

During testing, feed in samples from the completely hidden "Worms" class.

4

The system must flag them as "Zero-Day Anomalies" through Engine 1's reconstruction loss. If Engine 2 is reached, it will misclassify—proving the critical need for Engine 1.

5

Repeat for every class in the dataset, reporting the Zero-Day Detection Rate per class.

6. Evaluation Metrics

We introduce several metrics that go beyond the paper's standard Accuracy and F1-Macro, specifically chosen to demonstrate viability in real-world network environments.

MetricFormulaWhy It Matters in NIDS
Accuracy (TP+TN) / Total Overall correctness, but misleading with imbalanced data.
Precision TP / (TP + FP) Of all packets flagged as attacks, how many actually were? High precision = fewer false alarms.
Recall (DR) TP / (TP + FN) Of all actual attacks, how many were detected? High recall = fewer missed attacks (critical for security).
F1-Macro Harmonic mean of Prec & Recall Balanced metric that treats all classes equally, regardless of their frequency.
FAR (False Alarm Rate) FP / (FP + TN) How often does the system wrongly flag normal traffic? High FAR overwhelms SOC analysts.
MCC Correlation coefficient of predicted vs. true labels The gold standard for imbalanced datasets. Ranges from -1 to +1; higher is better.
Latency Time per packet (ms) Must be sub-millisecond for real-time packet inspection on edge routers.
Throughput (PPS) Packets Per Second Must be high enough to keep up with real network traffic rates without dropping packets.

The 5 Models Benchmarked

  • Proposed (1D ResNeSt + BiGRU): The full hybrid architecture from the paper, combining spatial and temporal feature extraction with residual connections and split-attention.
  • 1D ResNeSt Baseline: ResNeSt alone, without the BiGRU. Used to isolate the contribution of temporal modelling.
  • ResNet-GRU Baseline: Standard ResNet (no Split-Attention) with GRU. Used to isolate the contribution of the Split-Attention mechanism.
  • 1D-ResNet Baseline: Standard ResNet with skip connections but without Split-Attention or GRU. Used as a mid-complexity baseline.
  • 1D-CNN Baseline: A simple convolutional network without residual connections, split-attention, or temporal modelling. The simplest baseline.

Key Findings

  • Best F1-Macro: The Proposed model achieves the highest F1-Macro of 81.12%, validating that the combination of spatial (ResNeSt) and temporal (BiGRU) extraction genuinely outperforms any single-stage approach.
  • Lowest FAR: The Proposed model achieves the lowest False Alarm Rate (1.10%), meaning it generates the fewest incorrect alerts on normal traffic—critical for operational usability.
  • Highest MCC: An MCC of 0.895 is excellent for a highly imbalanced dataset. This confirms CTGAN was effective in synthesizing minority class samples.
  • Edge Viability: Even the most complex proposed model achieves >21,000 PPS at only 0.047ms latency per packet, making it practically deployable on modern edge network hardware.
